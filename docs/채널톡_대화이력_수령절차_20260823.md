# 채널톡 대화 이력 수령 절차

- 목적: 자체 챗봇을 채널톡과 **정량 비교**하고, 실제 이용자 질문으로 KB를 보강한다
- 대상 채널: `barrierfree.eumc.ac.kr` (pluginKey `a5de3b65-d01e-4207-9bec-01f3bd28c4a7`)
- 접속 계정: 뉴테크리모 (참고 영상 `docs/chatbot-assets/사용방법과 실제 챗봇 동영상/채널톡 로그인-뉴테크리모 계정.mp4`)

## 왜 필요한가

지금까지의 검증은 **내가 만든 77문항**이 기준이었다. 실제 이용자가 무엇을 묻는지는 반영되지 않았다.
채널톡 이력을 받으면 세 가지가 한 번에 해결된다.

1. **실제 질문 분포** — 합성 문항보다 나은 벤치마크가 된다
2. **채널톡의 실제 답변** — 그것이 곧 비교 대상 정답지다
3. **채널톡이 답하지 못한 질문** — KB 보강 대상이 그대로 나온다

특히 2번 때문에, 이력을 받으면 **운영 중인 채널톡 위젯에 테스트 질문을 쏘지 않아도 된다.**
위젯에 직접 질문하면 병원의 실제 상담함에 테스트 기록이 쌓이고 유료 AI 크레딧이 소모된다.

## 방법 A — 관리자 데스크에서 내려받기 (권장, 즉시 가능)

1. 채널톡 데스크 로그인 (뉴테크리모 계정)
2. **수신함** → 상담 목록
3. 상담 개수 우측 **다운로드** 버튼
4. **"메시지를 포함한 파일"** 옵션을 반드시 켠다 — 끄면 대화 내용이 빠진다

받는 파일은 Excel이며 시트가 나뉜다.

| 시트 | 내용 |
|---|---|
| UserChat data | 상담 기본정보(생성시각, 상태, 담당자) |
| **Message data** | **대화 전문 — 이게 핵심** |
| User data | 고객 정보 |
| Manager data / Team data | 담당자·팀 |
| UserChatTag data | 상담 태그 |

제한 사항

- 메시지 **포함** 시 한 번에 최대 **1만 건**, 미포함 시 10만 건
- **데이터 추출은 Pro 요금제 이상**에서 제공된다
- 기간이 길면 나눠서 여러 번 받는다

## 방법 B — Open API (전량 자동 덤프)

키 발급: 채널 설정 → 보안 및 개발 → API. 발급 후 두 값을 전달받으면 덤프 스크립트를 작성한다.

```
헤더:  x-access-key: <ACCESS_KEY>
       x-access-secret: <ACCESS_SECRET>

GET https://api.channel.io/open/v5/user-chats
GET https://api.channel.io/open/v5/user-chats/{userChatId}/messages?limit=500&since=<next>
```

- `limit` 은 1~500. 응답 루트의 `next` 를 다음 요청의 `since` 로 넘겨 전량을 수집한다
- 키는 `.env.local` 에만 두고 커밋하지 않는다 (`.gitignore` 확인 완료)

## 수령 후 작업 순서

1. `docs/chatbot-assets/channeltalk-export/` 에 원본 보관 (git 제외 — 개인정보 포함)
2. 이용자 발화만 추출 → 개인정보 마스킹 → 질문 목록 생성
3. 빈도·주제별로 분류하고, 기존 77문항과 커버리지 비교
4. 같은 질문을 자체 챗봇에 넣어 **채널톡 답변 vs 자체 답변** 대조
5. 채널톡이 답했는데 자체가 fallback 인 질문 → KB 보강 대상

## 주의

- 원본에는 **환자 개인정보가 포함될 수 있다.** 저장소에 커밋하지 않는다
- 분석용 파생 파일은 마스킹 후에만 만든다 (`lib/chatbot/log.ts` 의 `maskPII` 규칙 재사용)
- 병원 개인정보처리방침상 제3자 제공·보관 기간 제약이 있는지 확인이 필요하다
