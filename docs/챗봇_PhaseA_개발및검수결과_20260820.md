### 3.1 기능 (브라우저 실측)

| 항목 | 결과 |
|---|---|

### 3.3 접근성 — 채널톡 iframe에서 불가능했던 항목이 모두 동작

| 항목 | 채널톡 | 자체구축 실측 |
|---|---|---|
| 고대비 모드 | 적용 불가 | 패널·말풍선 `#000`/`#fff`/시안 테두리, 버튼·카드 `#ffe812` **자동 적용** |
| 글자확대 150% | 적용 불가 | 15px → **22.5px** (정확히 1.5배, rem 기반) |
| 확대 시 레이아웃 | — | 뷰포트 내 유지, 가로 스크롤 없음 |
| 키보드 | 제어 불가 | 런처 포커스 가능, ESC 닫기, 닫은 뒤 **포커스 런처 복귀** |
| 스크린리더 | 영문 `title="Channel chat"` | `role="dialog"` + `aria-modal` + `role="log" aria-live="polite"` + 화자 표시("편의지원 매니저:") |
| 모바일 390px | — | 풀스크린, 칩 44px 이상, 가로 스크롤 없음 |

### 3.4 검수 중 발견하고 수정한 결함 4건

| # | 결함 | 조치 |
|---|---|---|
| 1 | "와이파이 비밀번호" 같은 일반 문의가 개인정보 정책으로 **오분류** | 낱말 "비밀번호" 제거, 실제 주민번호·카드번호는 `containsPII()` 패턴으로 탐지 |

## 4. 플랜 대비 변경된 사항

### 4.1 별도 Supabase dev 프로젝트 생성 불가 (계획 변경)

플랜 4.2는 dev 전용 Supabase 프로젝트를 전제했으나, **Free 플랜 조직당 2개 한도가 이미 찼다.**
`ehwa-website` 외에 `woosung-hr-billing`(2026-08-19 생성)이 존재한다.

대응: Phase A 스키마는 기존 테이블을 전혀 건드리지 않는 **순수 가산 2개 테이블**이므로,
기존 프로젝트에 생성하고 **`env` 컬럼으로 preview/production 행을 분리**했다.
`chatbot_logs.env='preview'` 행만 지우면 dev 흔적이 남지 않는다.

> **Phase B 전에는 결정이 필요하다.** KB 문서 적재·임베딩·재색인은 운영 DB에서 하기에 부담이 크다.
> 선택지: ① Supabase Pro 전환 ② `woosung-hr-billing` 정리 ③ Phase B도 env 분리로 감수

### 4.2 Preview 보호 우회키 발급

플랜 11.1-#7에서 예상한 대로 Preview가 SSO 보호(302)로 막혀 있었다.
검수·자동화 테스트를 위해 **Protection Bypass for Automation** 키를 발급했다.
병원 담당자 검수 시에도 이 키가 붙은 URL을 전달하거나, Shareable Link를 별도 발급하면 된다.

### 4.3 채널톡과의 배타 노출 방식 확정

`NEXT_PUBLIC_CHATBOT_ENABLED` 가 `true`면 자체 위젯만, 아니면 채널톡 스니펫만 로드된다
(`app/layout.tsx`). 현재 Preview=true / Production=미설정(false).
**Phase D 전환은 Production에 이 변수를 `true`로 넣는 것만으로 완료**되며, 되돌리기도 같은 방식이다.
