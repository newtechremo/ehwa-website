## fallback 31건 재분류

### 개선 후보 20건

독립적으로 답할 수 있거나 replay가 보존한 직전 4턴으로 의도를 이어야 하는데도
`unanswerable`로 끝났다.

- 기능 범위·무엇을 질문할 수 있는지
- 병원 지도·층별 안내 링크
- 진료 예약 확인과 편의지원 예약 후 절차
- 카카오톡·이메일 신청 경로
- 자동차 방문 안내
- 지원 장애 유형과 장애복지카드가 없는 경우
- 진료과·채혈실 길찾기에서 현재 위치를 받은 뒤 이어 답하기
- “응”, “정문”, “주차장”처럼 앞 질문에 의존하는 짧은 후속 발화

이 20건은 같은 수의 새 고정문구를 만드는 문제가 아니다. 승인된 KB 질문 표현을 보강하고,
독립 질문은 FAQ/KB 직답으로, 후속 발화는 문맥 검색으로 분리한 뒤 동일 replay에서
재검증해야 한다.

### 적절한 거절·평가 노이즈 10건

타 병원, 시스템 프롬프트·내부 로직 질문, 의미 없는 테스트 입력, 답변할 질문이 없는 발화,
내부 지침 원문 요청은 현재 서비스 범위 밖이거나 원문도 답하지 못한 사례였다.

### 근거 부족으로 보수적 거절 1건

택시 승강장 위치는 Git KB에 확정 정보가 없어 임의 위치를 생성하지 않은 것이 맞다. 담당자
연결 또는 안내데스크 확인으로 끝내야 하며 ChannelTalk 문구를 사실 원문으로 승격하지 않는다.

## ChannelTalk 답변을 정답 원문으로 쓸 수 없는 이유

ChannelTalk은 위 20건에서 더 자연스럽게 응답했지만, 동일한 지도 질문에도 서로 다른 URL을
제시하고 문서에 없는 상세 동선을 생성한 이력이 있다. 그러므로 “ChannelTalk이 답했다”는
coverage 기준일 뿐 사실 정확성의 근거가 아니다. 전화번호·URL·지원 범위는 Git KB와 병원
담당자 승인으로 별도 검증한다.
